TL;DR — Multipliers dominate the cost of the multiply-accumulate units that train neural networks. In the logarithmic number system (LNS) a multiply is just an add, so we run all of training and inference in the log domain and approximate the one hard part, log-domain addition, with a 20-entry look-up table or plain bit-shifts. With 16-bit fixed-point words, the log-domain network lands within about 1% of floating point on four image datasets.

Figure 1. The correction terms Δ+(d) and Δ−(d) that make log-domain addition hard, with the look-up table (r = ½) and bit-shift approximations that replace them.

Abstract

The high computational complexity associated with training deep neural networks limits online and real-time training on edge devices. This paper proposed an end-to-end training and inference scheme that eliminates multiplications by approximate operations in the log-domain which has the potential to significantly reduce implementation complexity. We implement the entire training procedure in the log-domain, with fixed-point data representations. This training procedure is inspired by hardware-friendly approximations of log-domain addition which are based on look-up tables and bit-shifts. We show that our 16-bit log-based training can achieve classification accuracy within approximately 1% of the equivalent floating-point baselines for a number of commonly used datasets.

In the log domain, multiplying is the easy part

LNS stores a real number v as the base-2 logarithm of its magnitude, V = log2|v|, plus its sign sv. Multiplication and exponentiation get cheaper; addition gets harder, because the result needs a correction term that depends on how far apart the two operands are.

Multiply → add

U = X + Y

The output sign is the XNOR of the input signs. No multiplier needed.

Add → max plus a correction

Z = max(X, Y) + Δ±(|X − Y|)

Δ+(d) = log2(1 + 2−d) when the signs match, Δ−(d) = log2(1 − 2−d) when they differ. This is the term to approximate.

Exponentiate → multiply

w = xy  ↔  W = yX

For a positive base x; used for the soft-max. Subtraction is addition with the second sign flipped.

A fixed-point LNS word: log2|x| as a signed number with qi integer and qf fraction bits, plus the sign bit sx, for Wlog = 2 + qi + qf bits in total.

Two cheap approximations of log-domain addition

Training is already noisy (stochastic gradients, finite precision), so the question is how crude the Δ approximation can get before accuracy suffers.

Look-up table

Sample Δ±(d) over the range [0, dmax] at resolution r, i.e. 1/r points per unit interval, for a table of dmax/r entries. Sweeping both, dmax = 10 and r = ½ were enough: a 20-entry table for every operation. The soft-max proved more sensitive and uses a 640-entry table (r = 1/64).

Bit-shifts

Using ln(1 ± x) ≈ ±x for small x, the corrections become powers of two: Δ+(d) ≈ 1·2−d and Δ−(d) ≈ −1.5·2−d, which is just a shift. This generalizes an earlier bit-shift scheme to signed arithmetic, and it is equivalent to a look-up table with r = 1.

End-to-end training in the log domain

Matrix products map directly onto the operations above. The remaining pieces of training each get a log-domain form.

Activation: log-leaky ReLU

Leaky ReLU becomes llReLU: positive inputs pass through, negative ones get β added to their log magnitude. One hyper-parameter, and its derivative is equally simple in the log domain.

Weight initialization

A symmetric initial distribution fw maps to a Bernoulli sign and log magnitudes drawn from fW(y) = 2y+1 ln 2 · fw(2y), so weights start in the log domain directly.

Soft-max and cross-entropy

The soft-max and its gradient initialization p − y are written with log-domain exponentiation, addition and subtraction.

Fixed-point bit-width

A worst-case analysis says matching a 16-bit linear format (4 integer, 11 fraction bits) needs a 21-bit log word. In practice the experiments show the same width as the linear domain suffices.

Inputs are converted to the log domain offline in floating point; in a real-time system that conversion could use the same approximate operations.

Code

arnabsanyal/lnsdnn has the log-domain core in C (an OpenMP log-multiplier with a Python wrapper) and MLP experiments for all four datasets, in floating and fixed point, in both the linear and log domains. Trained models are stored with Git LFS. 

conda env create -f setup/environment.yml
conda activate lnsdnn
cd src && python setup.py install
cd 3_log_floatingpoint/mnist
python download_data.py               # fetch the dataset (see note below)
python train.py                      # inference with the included model
python train.py --is_training True   # train from scratch

The release is still in progress: the bit-shift experiments are not yet in the repository, and the dataset downloads need re-hosting. The README tracks what is left.

Scope and limitations

  • Small networks. The experiments train one-hidden-layer MLPs; larger convolutional networks are future work.
  • Hardware cost is not measured. The approach only pays off if the approximate log-domain adder is substantially cheaper in silicon than a multiplier. Co-optimizing the Δ approximation for accuracy and circuit complexity is future work.
  • 12 bits is not enough everywhere. At 12 bits, log-domain accuracy drops noticeably on Fashion-MNIST and EMNIST-Letters (Table 1); 16 bits closes the gap.
